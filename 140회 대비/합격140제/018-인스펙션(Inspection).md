#정보관리기술사 #SW공학 #인스펙션 #정적테스트
## 정의
Fagan의 인스펙션(Inspection)
- IEEE 1028-2008 기반의 가장 형식적인 동료검토 정적 테스트 기법
- 역할을 분리한 절차로 소프트웨어 산출물의 결함을 체계적으로 식별하는 리뷰기법
## 키워드
* IEEE 1028, 정적테스트, 형식적 리뷰, 중재자, 재작업, 워크스루
## 암기법
* 계개준검재후: 계획·개요·준비·검토회의·재작업·후속작업 (인스펙션 6단계)
## 특징
- 형식성: IEEE 1028 기반의 가장 형식적인 리뷰 방식
- 역할분리: 주재자·작성자·기록자·검토자 간 책임 구분
- 결함 조기식별: 산출물의 이상 사항을 체계적으로 조기 발견
- 메트릭 활용: 점검결과를 기록·분석해 프로세스 개선에 활용
## 목적
- 소프트웨어 산출물의 결함을 조기에 체계적으로 식별
- 검토 이력·메트릭 축적을 통한 프로세스 지속 개선
## 구성요소
- Plan: 리뷰계획 수립, 역할할당, 인스펙션 절차 개요 공유
- Do(준비): 개별 검토를 통한 문제 식별
- Check(검토회의): 객관적 검사, 문제 기록·분류, 승인/재작업 판정
- Action: 재작업(수정), 후속작업(조치완료 확인)
- 비교대상: 워크스루(저자중심의 유연한 리뷰방식)
## 구성도
```
[Plan: 리뷰계획·역할할당] → [작업물 설명] → [준비: 개별검토]
                                                    ↓
        [후속작업(조치확인)] ← [재작업(수정)] ← [검토회의: 문제기록/분류]
```
## 연관 토픽
- [[워크스루]] - 저자중심의 유연한 정적 리뷰 기법
- [[정적분석]] - 도구 기반 코드 품질 자동 점검 기법
- [[동료검토]] - 인스펙션이 속하는 상위 리뷰 유형
- [[품질보증(QA)]] - 인스펙션 결과가 반영되는 품질관리 활동
