#정보관리기술사 #SW공학 #SDD #스펙기반개발
## 정의
SDD(Spec-Driven Development)
- 명세(Spec)를 단일 진실 공급원(SSoT)으로 삼아 AI가 구현·테스트·문서를 생성하도록 통제하는 개발방법론
- 사람은 명세를 설계·검증·개선하고 AI가 실행을 담당하는 명세 중심 개발방식
## 키워드
* Spec First, SSoT, Executable Specification, TDD, BDD, Given-When-Then
## 암기법
* 스단설안피: 스펙정의·단일기준·AI가이드·피드백반영 (SDD 4대 핵심원칙)
## 특징
- 명세우선: 코드 작성 전 명세를 먼저 정의(Spec First)
- 단일기준: 명세가 구현·테스트·문서의 SSoT 역할 수행
- AI실행중심: AI가 구현·테스트·문서생성을 주도, 사람은 설계·검증
- 피드백순환: 오류수정·개선결과를 다시 명세에 반영
## 목적
- 명세와 구현의 불일치 문제 해소로 개발 일관성 확보
- AI 시대 사람의 역할을 기획·설계·관리 중심으로 재편
## 구성요소
- 스펙정의: 사용자시나리오, 요구사항, API 계약 정의
- 계획수립: 아키텍처설계, 데이터모델링
- 가드레일설정: 체크리스트, 테스트기준, 금지규칙
- AI구현생성: 코드/테스트/문서 자동생성
- 검증·피드백: 리뷰, 오류수정, 명세 갱신
- TDD/BDD 비교: TDD(실패테스트 중심), BDD(사용자행위시나리오 중심)
## 구성도
```
[Spec(SSoT)] → [계획수립] → [가드레일설정] → [AI 구현생성]
     ↑                                              │
     └──────── [검증·피드백: 명세 갱신] ←────────────┘
```
