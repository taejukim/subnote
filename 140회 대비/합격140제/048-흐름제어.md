#정보관리기술사 #디지털네트워크 #흐름제어 #SlidingWindow
## 정의
TCP 흐름제어(Flow Control)
- 송신자가 네트워크 환경과 수신자 상황을 고려해 데이터 전송 속도를 제어하는 전송계층 메커니즘
- Stop-and-Wait와 Sliding Window 방식으로 발전한 TCP 신뢰성 확보 기능
## 키워드
* Stop And Wait, Sliding Window, RWND, CWND, Silly Window Syndrome, Nagle, Clark
## 암기법
* 스슬: Stop-And-Wait(낮은효율)·Sliding Window(높은효율)의 2대 흐름제어 유형
## 특징
- 순차확인성: Stop-and-Wait는 1프레임 송신 후 ACK 확인
- 윈도우이동성: Sliding Window는 윈도우 크기만큼 ACK 없이 연속 전송
- 최소값결정성: 윈도우 크기는 Min(RWND, CWND)로 결정
- 오버헤드방지성: Nagle/Clark 알고리즘으로 Silly Window Syndrome 방지
## 목적
- 송신측 전송속도와 수신측 처리속도 간 불균형 해소
- 네트워크 혼잡 방지 및 전송 효율성 극대화
## 구성요소
- Stop-And-Wait: 1프레임 전송 후 ACK 대기(낮은 효율)
- Sliding Window: 윈도우 크기만큼 연속 전송, ACK로 윈도우 이동(높은 효율)
- 윈도우 크기: Min(RWND-수신측윈도우, CWND-혼잡윈도우)
- Silly Window Syndrome 해결: Nagle's Algorithm(송신측, 버퍼누적 후 전송), Clark's Solution(수신측, MSS단위 ACK)
## 구성도
```
[송신측] --Sliding Window(Min(RWND,CWND))--> [수신측]
    ACK 도착 → 윈도우 우측이동(열림) / 데이터전송 → 윈도우 좌측이동(닫힘)
Nagle(송신측: 버퍼누적→MSS단위 전송) + Clark(수신측: MSS단위 ACK) → Silly Window Syndrome 방지
```
