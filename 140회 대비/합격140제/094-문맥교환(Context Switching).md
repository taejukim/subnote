#정보관리기술사 #운영체제 #문맥교환 #ContextSwitching
## 정의
문맥교환(Context Switching)
- 멀티프로세스 환경에서 CPU를 다른 프로세스에 할당하기 위해 현재 프로세스 상태를 PCB에 저장하고 다음 프로세스 상태를 복원하는 과정
- 시스템 문맥·메모리 문맥·하드웨어 문맥 정보를 활용해 프로세스 재현을 지원하는 자원정보 교환 메커니즘
## 키워드
* 시스템 문맥, 메모리 문맥, 하드웨어 문맥, 디스패치, 타임아웃, PCB, 상태전이, 오버헤드
## 암기법
* 시메하: 시스템문맥·메모리문맥·하드웨어문맥 (문맥의 3대 유형)
## 특징
- 3대 문맥유형: 시스템문맥(PCB정보)·메모리문맥(Stack/Heap 등)·하드웨어문맥(레지스터·PC)
- PCB 기반 저장복원: 인터럽트·시스템콜 발생 시 PCB 저장 후 다음 프로세스 PCB 적재
- 오버헤드 발생: 인터럽트 처리·스케줄러 선택·PCB 저장복구 단계마다 시스템 자원 소비
- 쓰레드 경감효과: 경량 프로세스인 쓰레드는 문맥교환 시 전환정보량이 적어 오버헤드 감소
## 목적
- 멀티프로세스 환경에서 CPU 자원을 여러 프로세스가 공유하도록 지원
- 프로세스 중단 후 정확한 상태 복원을 통한 실행 연속성 보장
## 구성요소
- 문맥 유형: 시스템문맥(PID·State·Register), 메모리문맥(Stack·Heap·Data·Text), 하드웨어문맥(PC·Thread구조)
- 문맥교환 절차: 실행(P1) → 인터럽트/시스템콜 → PCB1저장 → PCB2적재 → 실행(P2) → ... → PCB1복원 → 실행(P1)
- 오버헤드 발생지점: 인터럽트 처리, 스케줄러의 다음 프로세스 선택, 디스패치(PCB 복구)
- 해결방안: 문맥교환 발생빈도 최소화(스케줄링 알고리즘 개선), 쓰레드 사용(경량화)
## 구성도
```
[P1 실행] → Interrupt/SysCall → PCB1 저장
                                    ↓
                              PCB2 적재 → [P2 실행]
                                    ↓ Interrupt/SysCall
                              PCB2 저장 → PCB1 적재 → [P1 재개]
```
