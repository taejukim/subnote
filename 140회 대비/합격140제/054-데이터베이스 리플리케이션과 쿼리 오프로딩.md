#정보관리기술사 #데이터베이스 #리플리케이션 #쿼리오프로딩
## 정의
DB 리플리케이션과 쿼리 오프로딩
- 리플리케이션은 Master/Slave로 나누어 데이터를 복제 저장해 일관성·가용성을 확보하는 방식
- 쿼리 오프로딩은 트랜잭션을 Update/Read로 분리해 DB 처리량을 향상시키는 기법
## 키워드
* Master DB, Slave DB, Update/Read 트랜잭션 분리, CDC, Staging DB, Load Balancing
## 암기법
* 일가 처량: 리플리케이션은 일관성·가용성, 오프로딩은 처리량 향상 (두 기법의 핵심 목적 구분)
## 특징
- 복제구조: Master-Slave(읽기부하 분산) 또는 Peer-to-Peer(SPOF 없음) 구조 선택
- 복제방식: 로그 기반(트랜잭션 로그) 또는 상태 기반(스냅샷) 복제
- 트랜잭션 분리: Update는 Master, Read는 Slave로 분리 처리
- CDC 연계: Staging DB를 경유하여 Master→Slave 변경 데이터 전달
## 목적
- 데이터 백업을 통한 일관성·가용성 향상
- DB 처리량 증가를 통한 전체 트랜잭션 성능 향상
## 구성요소
- Master DB: Create/Update/Delete 트랜잭션 수행 주체
- Slave DB: Read 전용, N개로 구성해 장애 시 HA 제공
- Staging DB: Master→Slave 복제의 경유지 역할
- Replication(CDC): Master 변경분을 Slave로 전달하는 로그 기반 기술
- Load Balancing: 다수 Slave DB 간 읽기 부하 분산
## 구성도
```
[Application]
   ├─Update─→ [Connection Pool] → [Master DB]
   │                                   │ Replication(CDC)
   │                                   ▼
   └─Read───→ [Connection Pool] → [Staging DB] → [Slave DB 1..N]
                                        (Load Balancing)
```
