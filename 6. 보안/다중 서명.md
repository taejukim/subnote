#정보관리기술사 #보안 #다중서명 #보안/암호화
Mult Signature
## 정의 
- 하나의 거래(트랙잭션)를 승인하기 위해 미리 지정된 여러개의 키(서명) 중 정해진 수 (M of N) 이상의 서명이 필요한 디지털 보안 서명

## 키워드
- M of N 서명, P2SH, [[스마트 컨트랙트]]

## 블록체인에서의 다중서명 절차도
![[1. ITPE/0. Sub-Note/99.attached_file/Pasted image 20260410003411.png|700]]

| 절차     | 핵심 기술                      | 설명                                                                                     |
| ------ | -------------------------- | -------------------------------------------------------------------------------------- |
| ① 조건설정 | - 스마트계약                    | - 모두가 서명하는 것이 아닌 정해진 조건을 미리 설정<br>- **M of N 서명**(3명중 2명 서명), 3of5를 조건 설정              |
| ② 키생성  | - 개인키, 공개키                 | - 각 서명자는 개인키(검증), 공개키 (주소생성)을 생성함<br>- 조건에 맞는 서명자 분만 아니라 모든 서명자가 생성                    |
| ③ 주소생성 | - 공개키                      | - 공개키를 통해 스크립트 해시 방식으로 거래 주소 생성<br>- **Pay to Script Hash** : 여러 서명자의 공개키와 조건설정으로 주소생성 |
| ④ 거래생성 | - 디지털 서명                   | - 송금자는 **멀티시그 주소**를 사용하여 거래를 생성, 서명 요구<br>- 거래는 트랜잭션 해시로 요약되고 각 서명자가 승인                |
| ⑤ 서명요청 | - 분산원장 기술                  | - 각 서명자는 거래의 서명할 기회를 갖고 개인키로 서명<br>- 서명 후에 서명된 데이터를 다른 서명자들에게 전달                       |
| ⑥ 서명검증 | - 서명검증<br>&nbsp;&nbsp;알고리즘 | - 트랜잭션 제출 전에 검증 과정 필요, 공개키로 유효성 확인<br>- 조건설정의 서명자 이상의 서명이 유효하면 제출 단계 이동                |
| ⑦ 제출   | - 합의 알고리즘                  | - 서명조건충족 : 조건설정에 사람이상이 개인키로 서명을 해야함                                                    |
| ⑧ 완료   | - 거래 변조 방지                 | - 모든 서명이 완료되고 트랜잭션이 블록체인에 기록되면 완료                                                      |

# 블록체인에서 다중 서명 구현을 위한 기법

| 비교 항목 | P2SH (Pay-to-Script-Hash) | 스마트 컨트랙트 (Smart Contract) |
|-----------|---------------------------|----------------------------------|
| 주요 사용<br>플랫폼 | - **비트코인 (Bitcoin)** | - **이더리움 (Ethereum)** 및 EVM<br>&nbsp;&nbsp;호환 체인 |
| 기본 개념 | - **M-of-N 규칙**이 담긴 '**스크립트**' 주소로 지급을 전송 | - **M-of-N 로직**이 프로그래밍된 '**계약**' 주소로 지급을 전송 |
| 자산 보관<br>위치 | - 스크립트에 의해 잠겨 있는 UTXO (Unspent Transaction Output) | - 스마트 컨트랙트 자체의 계정(주소) 잔액 |
| 구현 수준 | - 프로토콜 레벨 (비트코인 코어에 내장된 기능) | - 애플리케이션 레벨 (EVM 위에서 실행되는 별도 코드) |
| 주요 목적 | - 자산의 안전한 보관 및 공동 소유<br>- 다중서명, 커스터디, Escrow | - 안전한 자산 보관 + 거버넌스(DAO), 복잡한 금융 계약 등 |
