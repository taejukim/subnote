#정보관리기술사 #디지털서비스 #클라우드네이티브 #필수 #정리 #디지털서비스/클라우드_컴퓨팅/인프라

## 정의
마이크로 서비스 기반 클라우드 아키텍처, 클라우드 네이티브
- 마이크로 서비스로 구현한 클라우드 서비스 라이프 사이클 관리 아키텍처
- 클라우드 컴퓨팅의 이점을 최대한 활용하여 애플리케이션을 구축, 배포, 운영하는 소프트웨어 접근 방식
## 키워드
* MSA, Container, CI/CD, DevOps, Serverless, CNCF, 12-Factor App, 쿠버네티스, GitOps, IaC, Service Mesh, Observability
## 암기법
* 마컨C데서 (MSA, Container, CD, DevOps, Serverless)
* 조아인배 (조직: DevOps/Agile, 아키텍처: MSA/API, 인프라: 컨테이너/K8s, 배포: CI/CD)
## 특징
- 마이크로서비스: 독립 배포 가능한 소규모 서비스 단위로 분리
- 컨테이너 기반: Docker, Kubernetes를 활용한 경량 가상화
- 지속적 배포: CI/CD 파이프라인을 통한 자동화된 빌드/배포
- 탄력적 확장: 수요에 따른 자동 스케일링 및 자가 치유

## 등장배경 [리프MS데]
| 단계 | 내용 |
|------|------|
| **한계(As-Is)** | Monolith → 배포·확장·변경 비용 증가 / Lift&Shift → 클라우드 이전만으로 탄력성·장애격리 미달 |
| **요구(To-Be)** | 빠른 배포, 자동화 운영, 탄력적 확장, 장애 격리 |
| **기술 성숙** | Container, Kubernetes, CI/CD, DevOps 문화 보급 |
| **도입** | MSA + 컨테이너 + 파이프라인 기반 클라우드 최적화 설계 |

## 시험 대비 (2교시)
> **클라우드 일반 ≠ 클라우드 네이티브** — Capex·On-Demand·PaaS/SaaS만으로 특징을 끝내지 말 것

**1분 정의**
> 클라우드 네이티브란 MSA·컨테이너·DevOps·CI/CD를 기반으로 클라우드의 탄력성·확장성을 극대화하는 앱 개발·운영 패러다임이다.

**필수 키워드**: MSA, Container, Orchestration(K8s), CI/CD, DevOps, Service Mesh, API GW, IaC, Observability(M/L/T), Auto Scaling

**금지·주의**
- AI Agent, Datadog 등 **제품명** → 역할·기술명으로 치환
- CTEM·SWOT·Fog 등 **주제 이탈** 키워드로 분량 채우지 말 것
- 등장배경은 요구사항 나열 X → **한계→요구→기술성숙→도입** 인과로 작성
