#데이터베이스 #분산DB #확장성 #필수 #데이터베이스/NoSQL/분산
## 정의
대용량 데이터 분산 저장, 샤딩
- 대규모 데이터를 여러 데이터베이스 서버에 수평 분할하여 저장하는 기법
- 각 샤드(Shard)는 독립적인 데이터베이스로 동작하며 확장성 확보
- 물리적으로 다른 데이터 베이스에 데이터를 샤드라고 부르는 각각의 개별 파티션으로 수평 분할 방식으로 분산 저장하고 조회하는 기법
## 키워드
* Shard, Shard Key, 수평 분할, Hash Sharding, Range Sharding
## 암기법
* "해레디" - Hash, Range, Directory 기반 샤딩
## 샤딩 전략
| 전략 | 설명 | 장단점 |
|------|------|--------|
| Hash Sharding | 해시 함수로 샤드 결정 | 균등 분배, 범위 검색 어려움 |
| Range Sharding | 키 범위로 샤드 결정 | 범위 검색 용이, 핫스팟 발생 |
| Directory Sharding | 매핑 테이블로 샤드 결정 | 유연함, 조회 오버헤드 |
| Geo Sharding | 지역 기반 샤드 결정 | 지역성 활용, 관리 복잡 |

| shard key      | – (column)sharding된 테이블에서 shard를 선택하기 위한 식별자로 사용되는 칼럼                                                   |       |

| shard ID       | – shard DB를 식별하기 위한 식별자                                                                                 |       |
| proxy          | – 사용자 질의에 포함된 힌트를 해석하고, 해석된 힌트와 shard metadata를 이용하여 실제 질의 처리할 shard DB로 요청을 전달 역할을 하는 CUBRID 미들웨어 프로세스 |       |

## ■ 사딩 분할방법 [해레디]

| 분할방법                  | 분할원리                 | 설명                                                                 |
| --------------------- | -------------------- | ------------------------------------------------------------------ |
| **해**sh Sharding      | 해시 값을 얻어 샤드에 라우트     | – 해시함수를 사용하여 데이터를 균일하게 분산저장 하는 방법<br>– 샤드 추가 시 데이터 재정렬 필요          |
| **레**nge Sharding     | 범위 기준 샤드에 라우트        | – 특정 범위 기준으로 분산 저장<br>– 샤드 추가시 재정렬 비용 발생<br>– 일부 샤드에 데이터가 집중될 수 있음 |
| **디**rectory Sharding | 별도 조회 테이블 사용해 샤드 라우팅 | – 샤드 목록을 테이블로 관리하여 분산처리<br>– 목록 테이블이 단일 장애 포인트                     |
