#정보관리기술사 #데이터베이스 #동시성제어 #비관적동시성제어
## 정의
비관적 동시성제어(Pessimistic Concurrency Control)
- 다중 트랜잭션 환경에서 충돌이 빈번하다는 가정 하에 트랜잭션 수행 중 미리 Lock으로 직렬성을 보장하는 기법
- 사전 Locking 기반 강한 일관성 확보 동시성 제어
## 키워드
* 2PL, Lock, S/X Lock, Deadlock, Serializability, 강일관성
## 암기법
* 사락대보: 사전락·대기·보장
## 특징
- 사전 락성: 트랜잭션 시작 시 자원 락
- 강한 일관성: 충돌 원천 차단
- 대기 발생성: 락 경합 시 다른 TX 대기
- 데드락 위험성: 상호 락 대기로 교착 가능
## 목적
- 충돌이 잦은 환경에서 데이터 무결성 보장
- 금융·결제 등 강한 일관성 요구 영역 적용
## 구성요소
- 기본 가정: 충돌이 자주 발생
- 접근 방식: 미리 Lock 수행
- 대표 기법: [[2PL]] (2 Phase Locking)
- 메커니즘: 읽기 전 Lock → 갱신 후 Unlock
- 충돌 시 처리: 다른 트랜잭션 대기(교착 가능)
- 주요 비용: Lock 유지·대기 시간
- 데이터 무결성: 강력하게 보장
- 장점: 데이터 일관성 보장
- 단점: 병목·Deadlock 발생 가능
- 적합 환경: 은행 계좌이체, 금융 트랜잭션
- 낙관적 동시성제어 비교: 낙관(검증), 비관(사전 락)
## 구성도
```
[TX1] 읽기 전 Lock → 처리(다른 TX 차단) → 검증 불필요 → Commit/Unlock
                       ↑
[TX2] Lock 대기 ──────┘ → Lock 획득 후 진행
```
