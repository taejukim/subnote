## 정의
지리적으로 분산된 데이터베이스, 분산 DB
- 네트워크로 연결된 여러 사이트에 데이터를 분산 저장하고 통합 관리하는 시스템
- 위치 투명성, 복제 투명성, 분할 투명성을 제공하여 단일 DB처럼 사용


* 투명성, 2PC, 복제, 분할, CAP, 분산 트랜잭션
## 암기법
* "위복분장병" - 위치, 복제, 분할, 장애, 병행 투명성
## 분산 데이터베이스 투명성 [위복병분장]

| 투명성        | 주요개념                                                                                                      | 장점                               | 단점                     |
| ---------- | --------------------------------------------------------------------------------------------------------- | -------------------------------- | ---------------------- |
| **위**치 투명성 | 사용자나 응용프로그램이 접근할 데이터의 물리적 위치를 알아야 할 필요가 없는 성질. 이를 보장하기 위해 DBMS는 Distributed Data Dictionary Directory가 필요 | Application 단순화<br>자유로운 Data의 접근 | 이중처리로 속도 저하<br>저장공간 낭비 |
| **복**제 투명성 | 응용프로그램이 접근할 데이터가 물리적으로 여러 곳에 복제되어 있는지 여부에 대해 알 필요가 없는 성질                                                  | 상향식 점진적 확장제공                     | 이질형 시스템 구현 시 복잡        |
| **병**행 투명성 | 다중 사용자가 동시에 분산 DB에 트랜잭션을 수행해도 결과에 이상이 발생하지 않는 성질                                                          | 자원사용 극대화                         | 복잡한 Locking            |
| **분**할 투명성 | 사용자가 하나의 논리적 릴레이션이 여러 단편으로 분할되어 각 단편의 사본이 여러 Site에 저장되어 있음을 알 필요가 없는 성질, 성능향상, Fragmentation을 위한 설계 필요    | Bottle neck 방지<br>시스템 성능 향상      | 충분한 설계기술 필요            |
| **장**애 투명성 | 분산되어 있는 각 지역의 시스템에 이상이 생기더라도 무결성을 보존할 수 있는 성질 (2PC 활용)                                                    | 장애처리 구현 단순                       | 장애원인규명 복잡              |

## 2PC (2단계 커밋)
```
[조정자]                [참여자들]
   │                       │
   │──── Prepare ─────────→│
   │←─── Ready/Abort ──────│
   │                       │
   │──── Commit/Rollback ─→│
   │←─── ACK ──────────────│
```

## ■ 분산 DB 설계 전략 [탑버하]

| 전략         | 설명                                                                                                          |                             |             |
| ---------- | ----------------------------------------------------------------------------------------------------------- | --------------------------- | ----------- |
| Top Down   | – 중앙 집중 DB 설계와 같이 전체 설계 후 분산 DB 설계<br>– 기존 데이터베이스가 존재하지 않는 상태에서 설계                                          |                             |             |
| Bottom Up  | – 지역 별 설계 후 전사적 관점에서 통합(이기종 데이터베이스와 연동하기 위한 게이트웨이 필요)<br>– 이미 존재하는 데이터베이스를 통합하는 방법                          |                             |             |
| Hybrid     | – 데이터베이스 통합 시 양 방식을 혼합하여 활용하는 방식, DB들의 데이터 복잡도가 심한 경우 적용<br>– 이미 존재하는 데이터베이스의 복잡도가 심하여 Bottom Up 적용이 어려운 경우 |                             |             |
| **분**할 투명성 | 사용자가 하나의 논리적 릴레이션이 여러 단편으로 분할되어 각 단편의 사본이 여러 Site에 저장되어 있음을 알 필요가 없는 성질, 성능향상, Fragmentation을 위한 설계 필요      | Bottle neck 방지<br>시스템 성능 향상 | 충분한 설계기술 필요 |
| **장**애 투명성 | 분산되어 있는 각 지역의 시스템에 이상이 생기더라도 무결성을 보존할 수 있는 성질 (2PC 활용)                                                      | 장애처리 구현 단순                  | 장애원인규명 복잡   |

## 시험 대비 (1교시) — 투명성 1문장 정의
| 투명성 | 시험용 1문장 |
|--------|-------------|
| **위치** | 물리적 저장 위치를 응용이 알 필요 없음 → 단일 DB처럼 접근 |
| **복제** | 데이터가 여러 Site에 복제되어 있어도 응용이 인지하지 않음 |
| **병행** | 다중 사용자·트랜잭션이 동시 수행되어도 결과에 이상 없음 |
| **분할** | 논리적 1개 릴레이션이 분할·분산 저장되어도 단일 DB처럼 사용 |
| **장애** | Site 장애 시에도 무결성 유지·Failover로 서비스 지속 |

> 투명성 = **분산 사실을 사용자/응용에게 숨기는** 성질 (복제·분할 기법 자체 설명 X)

**금지·주의**: 샤딩·MSA·리전 분산은 III절 보조만 — 본문은 5대 투명성 + 개념도
