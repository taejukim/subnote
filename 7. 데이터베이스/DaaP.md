#정보관리기술사 #데이터베이스 #DaaP #데이터베이스/빅데이터/분석
Data as a Product
## 정의
- 데이터를 단순한 저장 자산이 아닌, 최종사용자 중심의 독립적인 제품으로 관리하느 데이터 거버넌스 및 아키텍처 패러다임
## 키워드
- 데이터 메시, 데이터 패브릭, 데이터 리니지, 데이터 카탈로그, API 기반, ETL, [[클라우드 네이티브]]

## 구성요소
|구분|구성요소|
|---|---|
|조직 관점|- Data Product Owner- 데이터 거버넌스 체계- 도메인 기반 운영 구조|
|사용자 관점|- Data Consumer- 데이터 카탈로그 및 검색 기능- 사용자 피드백 및 만족도 관리|
|기술/운영 관점|- 자동화된 데이터 파이프라인- API 기반 데이터 서비스- 모니터링 및 로깅 시스템|
|품질/보안 관점|- 데이터 품질 관리 체계- 메타데이터 및 Data Lineage- 보안 및 접근 제어 정책
## 특징
|특징|설명|
|---|---|
|분석을 위한 깔끔한 고품질 데이터 세트|- 데이터 제품의 신뢰성과 신뢰도를 보장|
|메타데이터와 의미 체계|- 비즈니스 사용자가 데이터 제품을 컨텍스트와 함께 발견하고 이해할 수 있도록 함|
|데이터 세트 간의 상호 운용성|- 데이터 세트는 함께 작동하여 편향되지 않은 데이터 인사이트를 제공|
|도메인 간 공유 가능성|- 데이터 제품은 여러 도메인과 앱에서 데이터를 간편하게 공유|
|접근성|- 데이터 소비자는 원하는 인사이트를 쉽게 제공 받음|
|재사용성|- 다른 제품을 구축하는 데 사용할 수 있는 구성 가능한 모듈식 요소로 구성|

## 핵심원칙
| 특징                         | 설명                                         |
| -------------------------- | ------------------------------------------ |
| 도메인 소유권 (Domain Ownership) | - 데이터를 가장 잘 아는 팀이 직접 관리- 데이터 메시의 원칙        |
| 데이터 제품                     | - ‘데이터셋’이 아니라 ‘사용자를 가진 제품’                 |
| 표준화 & 상호운용성                | - 여러 도메인의 데이터 제품이 서로 호환되어야 하는 공통 규칙을 가져야 함 |
| 관측 가능성                     | - 품질 / 지연 / 스키마 변동을 모니터링                   |
