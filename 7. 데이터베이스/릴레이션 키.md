#정보관리기술사 #데이터베이스 #릴레이션키 #데이터베이스/관계모델
## 정의
- 하나의 릴레이션 내에서 각각의 튜플들을 유일하게 식별할 수 있는 속정의 집합
## 키워드
- 슈퍼키, 후보키, 기본키, 대체키, 외래키

## 암기법
- 키도출절차 : 유최대
	- 유일성 검증, 최소성 검증, 엔티티 대표성
- 키 유형 및 제약유형 : 슈후기대외
	- 슈퍼키, 후보키, 기본키, 대체키, 외래키
## 키 도출 절차
- 결정자 도출(유일설 검증) → 슈퍼키 선정(최소성 검증) → 후보키 선정(엔터티 대표성) → 기본키 결정
1. 유일설 검증 : 함수적 종속성 확인을 통해 유일성 검증
2. 최소성검증 : 최소성 확인 후 키 설정(후보키 선정)
3. 엔티티 대표성 : 후보키 중 엔티티 대표성 기준 기본키 확정

## 키 유형 및 제약 유형

| 유형                      | 내용                                | 특성                     |
| ----------------------- | --------------------------------- | ---------------------- |
| **수**퍼키 (super key)     | 유일성은 만족하지만 최소성은 만족하지 않는 키         | 유일성                    |
| **후**보키 (candidate key) | 키의 특성인 유일성과 최소성 모두를 만족하는 키        | 유일성<br>최소성<br>Not null |
| **기**본키 (primary key)   | 후보키 중 하나를 대표로 선정하여 사용하여 기본키로 정의   | ^                      |
| **대**체키 (alternate key) | 여러 후보키들 중에서 기본키로 선정되고 남은 나머지      | ^                      |
| **외**래키 (foreign key)   | 릴레이션 속성의 집합이 다른 릴레이션에서 기본키 이용되는 키 |                        |
## 제약유형

| 제약유형 | 설명 | 구현형태 |
|---------|------|---------|
| 본질적 제약 | 데이터 모델의 구조적인 특성으로 인한 제약<br>반드시 주 키(primary key)가 있어야 하고 테이블의 각 셀이 단일 값을 가짐<br>(1차 정규화의 의미) | Primary Key<br>Unique Key |
| 내재적 제약 | 데이터 의미를 정확히 표현하고 오류 방지<br>DB 스키마에 지정하는 제약<br>영역 제약, 참조 무결성 제약 | Foreign Key, Check,<br>Default, Not null |
| 명시적 제약 | PGM 명시하거나 사용자의 수작업으로 생성 | Programmatically |
