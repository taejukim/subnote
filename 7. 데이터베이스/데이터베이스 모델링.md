#정보관리기술사 #데이터베이스 #데이터베이스모델링 #데이터베이스/빅데이터/분석
## 정의
- 현실 세계의 비즈니스를 추상화 하여 논리적이고 구조화된 데이터 모델로 표현하는 활동

## 키워드
- 요구사항 분석, 개념 모델링, 논리 모델링, 물리 모델링

## 암기법
- 원칙 : 커상논
	- 커뮤니케이션 원칙
	- 모델 상세화 원칙
	- 논리적 표현 원칙
- 모델링 단계 : 개논물, 주후핵관, 속엔이 물논반
	- 개념모델링, 논리모델링, 물리 모델링
		- 개념모델링 : 주제 영역 정의, 후보 entity 선전, 핵심 Entity 정의 관계정의
		- 논리모델링 : 속성정의, Entity 상세, 이력 관리 정의
		- 물리모델링 : 물리 환경 조사, 논리모델 변환, 반정규화

## 원칙 

| 원칙 | 내용 |
|------|------|
| **커**뮤니케이션 원칙<br>Communication Principle | 모든 사람들의 이해와 분명한 파악이 가능한 모델 제시<br>최종사용자와 모든 이해관계자들을 최대한 고려<br>**(대상)** 최종사용자, 시스템분석가, DB관리자, 타 전문가 |
| 모델링**상**세화 원칙<br>Granularity Principle | 조직 정부구조의 최소 공통 분모 제시<br>**(분할)** 복잡한 구조 및 프로세스는 요소단위로 분할<br>**(제거)** 불필요한 구조와 중복은 협의통해 제거 |
| **논**리적표현 원칙<br>Logical Representation Principle | 조직의 비즈니스를 그대로 논리적으로 반영<br>**(분석)** 경험에의한 섣부른 판단 보다는 절차 준수<br>**(구체화)** 단기간의 솔루션을 구체화 시도는 지양 |

## 고려사항

| 고려사항  | 설명                                       |
| ----- | ---------------------------------------- |
| 무결성   | – 갱신, 삽입, 삭제 등 연산 수행한 뒤에도 데이터 값은 제약조건 만족 |
| 일관성   | – 두 데이터 값 사이나 특정 질의에 대한 응답들에 모순성 없이 일치   |
| 회복    | – 시스템 장애가 발생했을 때 장애 발생 직전 일관된 DB 상태로 복구  |
| 보안    | – 불법적인 데이터 변경이나 손실, 노출에 대한 보호            |
| 효율성   | – 응답 시간 단축, 저장 공간 최소화, 시스템 생산성           |
| DB 확장 | – 시스템 운영에 영향을 주지 않으면서 계속적인 추가            |
## 데이터 모델링 단계별 절차

| 단계     | 절차               | 내용                                                             | 고려사항                               |
| ------ | ---------------- | -------------------------------------------------------------- | ---------------------------------- |
| 개념 모델링 | 주제 영역 정의         | 데이터의 최상위 집합을 구분하는 단계<br>전사적 관점에서 데이터 분류 수행                     | 중복 최소화, 확장성 보장, 관련성 및 편의성 확보       |
|        | **후**보 Entity 선정 | Entity가 될 가능성이 있는 후보 수집<br>**(문서, 인터뷰, 관련서적, 전문가 경험)**         | 함부로 제외 금지, 현업참여, 상세화 금지            |
|        | **핵**심 Entity 정의 | 후보 중 핵심 Entity 선별<br>**본질식별자, 서브타입** 등 정의                      | 관리여부, 집합여부, 동질성 여부, 독립성 여부 확인      |
|        | **관**계 정의        | 관련이 있는 Entity간의 연관성을 정의<br>**(1:1, 1:M, M:M, 순환, Arc)**        | 항상 두 Entity간 존재, 양방향, 항상 두개의 관점 존재 |
| 논리 모델링 | 속성 정의            | 분해 불가한 최소의 데이터 단위로 상세화<br>속성 후보도출 후 검증 및 확정                    | 최소 분할은 필수, 필요시 분할 후 통합, 업무요구에 근거   |
|        | **E**ntity 상세화   | 식별자 확정, 정규화, M:M 관계 해소<br>**(1차 → 2차 → 3차 → BCNF → 4차)**       | 속성은 하나의 값, 속성간 종속 제거, 참조무결성 규칙     |
|        | **이**력 관리 정의     | 정보로서의 활용성 추적성 확보<br>**시점, 선분 (발생이력, 변경이력, 진행이력)**              | 물리적 성능 고려, 일자의 종료점 선택, 키 및 인덱스 고려  |
| 물리 모델링 | **물**리 환경 조사     | 시스템 구축 환경 조사 및 분석 확정<br>**HW 자원(CPU, Memory, disk), OS, DBMS** | 사용자 관리기법, 백업정책, 보안관리 정책 고려         |
|        | **논**리모델 변환      | 테이블, 속성, 관계, 제약조건 등 전환<br>수퍼/서브타입 모델 전환                        | PK최적화, 통합여부 고려, 의사결정을 통한 조정 및 합의   |
|        | **반**정규화         | 성능, 개발편의성, 운영단순성 확보<br>**(테이블 분할 및 중복, 중복 및 집계 컬럼)**           | 반정규화 최소화 원칙, SQL이나 인덱스 조정을 우선 고려   |
