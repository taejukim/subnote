#정보관리기술사 #데이터베이스 #데이터베이스회복기법 #데이터베이스/트랜잭션/회복
## 정의
- Media, Syntax, Fat-finger와 같은 문제로 장애 발생 시 회복 기법을 이용하여 일관성 무결성, 가용성을 홥고 및 보장 수행하는 기법

## 키워드
- REDO, UNDO, 즉시갱신, 지연갱신, 체크포인트, 그림자 페이지

## 트랜잭션 유형별 사용률 [하소사 미하 신인 팻파]

| 구분 | 장애 유형 | 상세 설명 |
|------|----------|----------|
| H/W | – Media 장애 | – CPU, Memory, Disk 문제 발생되어 데이터가 파손되는 장애<br>– SCN Mismatch, Data Block Corruption |
| | – H/W 성능 저하 | – 낮은 사양의 H/W로 인한 처리 속도 지연, 누락 |
| S/W | – Syntax 장애 | – 프로그램 오류나 사용 용량, 여유 공간 부족으로 발생 |
| | – Instance 장애 | – 시스템이 비정상적인 요인으로 프로세스 중단 |
| 사용자 | – Fat-finger Error | – 사용자 실수로 테이블 삭제, 잘못된 트랜잭션 처리<br>– 일관성 문제 발생 및 데이터 소실 발생 |
| | – Parameter Error | – DB를 구성하는 주요 Parameter 설정 오류 |

## 회복기법 유형 [회로(즉지)체그아]

| 기법 | 동작 방식 | 상세 설명 |
|------|----------|----------|
| 즉시 갱신 기법 | 트랜잭션 시작 → 갱신 → 갱신 → 장애 발생<br>갱신 내용을 Log와 DB에 즉시 반영<br>장애 발생 시 **"UNDO"** 연산으로 복구 | – 트랜잭션 갱신 Log, DB 반영<br>– 장애시 Log 파일 참조 UNDO 연산 |
| 지연 갱신 기법 | 트랜잭션 시작 → 갱신 → 갱신 → 장애 발생<br>갱신 내용을 Log에만 기록, DB 반영은 종료 후<br>장애 발생 시 Log **"폐기"** (미종료), REDO (종료) | – 트랜잭션 갱신 Log 반영(DB 종료후 반영)<br>– 장애시 Log 폐기(미종료), REDO 연산(종료) |
