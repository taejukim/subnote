### 데이터 독립성을 위한 스키마 요소

| Schema     | 설명                                                       | 뷰                                      |
| ---------- | -------------------------------------------------------- | -------------------------------------- |
| 외부(서브) 스키마 | - 응용/사용자 입장에서 바라본 DB의 측면<br>- View 단계가 여러 개의 사용자 관점 구성   | 각 사용자 뷰<br>(사용자 관점 접근하는 특성에 따라 스키마 구성) |
| 개념 스키마     | - Database의 논리적 구조<br>- 사용자 관점의 통합으로 조직 전체의 DB 기술        | 사용자 공통체의 뷰(통합 관점)                      |
| 내부 스키마     | - 저장장치 입장에서 데이터베이스 전체가 저장되는 방법을 명세<br>- 내부 단계, 내부 스키마 구성 | 물리적 또는 저장 뷰(물리적 저장 구조)                 |

---

### 3단계 스키마를 통한 데이터 독립성 보장 영역

| 독립성 | 내용 | 요구 능력 |
|--------|------|----------|
| 논리적 독립성 | - 개념 스키마 변경에 외부 스키마 영향 제거<br>- 논리적 구조↔응용 프로그램 | - 하나의 논리적 데이터 구조로 응용프로그램에서 요구한 논리적 구조로 Mapping 지원 능력 |
| 물리적 독립성 | - 내부 스키마가 변경에 외부/개념 스키마의 영향 제거 | - 하나의 논리적 구조와 여러 상이한 물리적 구조의 Mapping 지원 능력 |
