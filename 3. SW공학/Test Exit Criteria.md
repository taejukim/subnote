#정보관리기술사 #SW공학 #TestExitCriteria #테스트 #NEW
## 정의
Test Exit Criteria
- 추정 결함밀도·커버리지·일정·비용 등 정량 지표로 테스트 종료 시점을 판단하는 완료 조건
- 단일 테스트 레벨 또는 특정 목적 테스트의 종료 기준
## 키워드
* 완전성, 목적, 기준, 커버리지, 리스크, 스케줄
## 암기법
* 완목기커리스: 완전성·목적·기준·커버리지·리스크·스케줄
## 특징
- 정량 판단성: 수치화된 지표로 종료 결정
- 다기준성: 완전성·목적·커버리지 등 복합 조건
- 우선순위성: 치명 결함 100% 해소 등 단계 원칙
- 진입 연계성: Entry Criteria(빌드·개발자 재테스트 완료)와 쌍
## 목적
- 테스트 종료 시점의 객관적·합리적 결정
- 품질 목표 달성 여부의 명확한 합의
## 구성요소
- 테스트 완전성: 전 TC 수행, Critical/Major 결함 없음
- 테스트 목적: 초기 품질목표 달성(예: 사용자 만족 ≥90%)
- 테스트 기준: 설정 수준·Exit 기준 충족(예: TC ≥90%)
- 테스트 커버리지: 고객 요구 충족 판정(필수 기능 구현)
- 테스트 리스크: 예상 관련 위험 제거
- 테스트 스케줄: 계획된 테스트 기간 종료
- 원칙: 필수 기능 정상, 산출물 문서화, 고우선 버그 해소
## 구성도
```
[Entry] 빌드·개발자 재테스트 완료
   ↓
테스트 수행 ← 완·목·기·커·리·스 지표 모니터링
   ↓
[Exit] 조건 충족 → 테스트 종료 / 미충족 → 지속
```
