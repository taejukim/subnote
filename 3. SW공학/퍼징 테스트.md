## 정의
퍼징 테스트(Fuzzing Test)
- 제품에 랜덤 데이터를 입력해 예외·오류를 분석하고 보안 취약점을 찾는 테스팅 기법
- 비정상 입력으로 크래시·취약점을 유도하는 동적 검증
## 키워드
* Valid/Invalid Case Fuzzing, 보안취약점, 블랙박스, 화이트박스, 그레이박스
## 암기법
* 대상입케실모분: 대상분석·입력선정·케이스생성·실행·모니터링·분류해결
## 특징
- 랜덤/비정상 입력: 예외 경로·취약점 유발
- 생성 다양성: Dumb·Smart·Evolutionary
- 투입 전략성: Valid / Invalid Skip / Invalid Fail
- 가시성 스펙트럼: Black·White·Gray box 퍼징
## 목적
- 버퍼오버플로 등 보안 취약점 조기 발견
- 비정상 입력에 대한 견고성·복구력 검증
## 구성요소
- 대상 분석: App·Framework·프로토콜·소스·역공학
- 입력 선정: 미디어·문서·프로토콜·비정상 값
- TC 생성: Generation·Mutation(FuzzBox, Seed)
- 실행·모니터링: CLI 실행, system/kernel log, crash stack
- 분류·해결: null deref, /0, buffer overflow 수정
- 생성: Dumb(변이)·Smart(모델)·Evolutionary(응답 기반)
- 투입: Valid / Invalid Skip / Invalid Fail
- 변조: Mutation-based / Generation-based
## 구성도
```
대상분석 → 입력선정 → TC생성(Mutate/Generate)
    → 실행 → 모니터링(로그/Crash) → 분류·수정
[유형] Dumb/Smart/Evo | Valid/Skip/Fail | BB/WB/GB
```
