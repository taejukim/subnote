#정보관리기술사 #SW공학 #TDD #Agile #NEW
## 정의
TDD(Test Driven Development)
- 테스트케이스를 먼저 개발하고 이를 통과하는 실제 코드를 작성하는 Agile 개발 방법론
- Simple Code 추구를 위해 테스트 자동화와 짧은 반복을 전제로 함
## 키워드
* 요구사항, 테스트, 구현, 리팩토링, Simple Code, RED-GREEN-REFACTOR
## 암기법
* 요테구리: 요구사항·테스트·구현·리팩토링
## 특징
- 테스트 선행성: 코드 작성 전 실패하는 테스트부터 작성
- 최소 구현성: 테스트 통과에 필요한 최소한의 코드만 작성
- 반복 개선성: RED→GREEN→REFACTOR를 N번 반복
- 자동화 기반성: 테스트 자동화로 짧은 주기 검증
## 목적
- Simple Code 달성과 중복·복잡성 제거
- 테스트 자동화로 품질·회귀 안정성 확보
## 구성요소
- 요구사항: 사용자·BA·제품개발자가 Requirement Story 작성
- 테스트 작성: 기능 요구사항에 대한 인터페이스 개발
- 구현: 테스트를 통과하는 실행 가능 코드 신속 작성
- 리팩토링: 중복·임시코드 제거, 모듈화, 디자인패턴 적용
- 체크인: 모든 테스트가 통과하는 Clean Code 저장
- RED: 실패하는 테스트 작성
- GREEN: 테스트를 통과시키는 작은 코드 작성
- REFACTOR: 중복·긴 메서드·큰 클래스 등 효율적 개선
## 구성도
```
요구사항 → Test-case → Code(Simple Code)
              ↑            │ Bad Smell? → 단순화
              └─ N번 반복 ─┘
         [테스트 자동화]
RED(실패 테스트) → GREEN(최소 코드) → REFACTOR(중복 제거)
```
