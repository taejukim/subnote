## 정의
요구사항 추적표(RTM, Requirements Traceability Matrix)
- 요구사항과 설계·구현·시험·산출물 간 양방향 연결 관계를 표로 관리하는 추적성(Traceability) 도구
- 요구의 출처·구현·검증 상태를 가시화하여 누락·과잉·변경 영향을 통제
## 키워드
* RTM, Forward Traceability, Backward Traceability, Baseline, Change Control
## 암기법
* "전후기변" - 전방추적, 후방추적, 기준선(Baseline), 변경통제
## 특징
- 전방 추적(Forward): 요구 → 설계/코드/테스트로 구현·검증 경로 확인
- 후방 추적(Backward): 산출물 → 원 요구로 근거·필요성 확인(고아 산출물 방지)
- 기준선(Baseline): 합의된 요구 집합을 고정하고 이후 변경을 공식 절차로 관리
- 양방향·완전성: 커버리지(미구현/미시험 요구)와 추적 끊김을 조기에 식별
## 목적
- 요구 누락·과도 구현 방지 및 시험 커버리지 확보
- 변경 영향 분석(Impact Analysis)과 감사·인수 증빙 제공
## 구성요소
- 식별자(ID): 요구·설계·모듈·테스트케이스 고유 ID 매핑
- 추적 링크: 요구↔설계↔코드↔TC↔결함의 관계 기록
- 상태/커버리지: Implemented, Tested, Passed 등 진행·검증 상태
- 변경통제: Baseline 대비 변경 요청(CR)·승인·재추적 갱신
## 구성도
```
[이해관계자 요구] ──Forward──▶ [설계] ──▶ [구현] ──▶ [테스트]
       ▲                         │         │         │
       └──────── Backward ───────┴─────────┴─────────┘
                              │
                         ┌────┴────┐
                         │  RTM    │  ID · Link · Status
                         │ Baseline│  Change Control
                         └─────────┘
```
