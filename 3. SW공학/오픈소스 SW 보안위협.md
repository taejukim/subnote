#정보관리기술사 #SW공학 #오픈소스보안 #보안위협 #NEW
## 정의
오픈소스 SW 보안위협
- 소스코드가 공개되어 사용권 범위 내 자유 사용·변경·배포가 가능한 오픈소스의 특성으로 발생하는 관리·기술 측면 보안 위협
- Zero Day·Log4j 등 공개 취약점 악용, 타이포스쿼팅·악성코드 삽입, 패치 지연 등이 대표 위험
## 키워드
* Zero Day, Log4j, 타이포스쿼팅, Scan Tool, Hash(SHA-256), Sandbox, 시큐어코딩
## 암기법
* 관사프조 / 기공조장: 관리(사용·프로세스)·기술(공격·조치) 위협 대응
## 특징
- 현황 부재: 배포 자유로 사용 현황 파악 곤란
- 맹목 신뢰: 커뮤니티 소스 무검증 사용·타이포스쿼팅
- Zero Day 취약: 공개 소스로 공격 코드 확산 용이
- 패치 의존: 배포사 패치·호환성 문제로 조치 지연
## 목적
- 오픈소스 사용·프로세스·기술 측면 위협 식별
- Scan·Hash·Sandbox·자동 업데이트 등으로 보안 관리 강화
## 구성요소
- 관리-위협: 사용현황 부재, 맹목적 사용, 취약점 점검 부재, 패치 조치 지연
- 관리-대응: Scan Tool, Hash 확인, 보안점검 프로세스, 전문업체 점검
- 기술-위협: Zero Day, 악성코드(RCE·크립토재킹), 자체조치 불가, 패치 호환성
- 기술-대응: Sandbox 테스트, 시큐어코딩, 업데이트 자동화, IPS/FW(CWE·CVE)
## 구성도
```
[관리적] 사용·프로세스 위협 → Scan/Hash/프로세스/전문가
[기술적] 공격·조치 위협 → Sandbox/시큐어코딩/자동갱신/IPS·FW
```
