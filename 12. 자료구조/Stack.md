#정보관리기술사 #자료구조 #Stack #자료구조/선형구조
## 정의
- 나중에 삽입된 사료가 가장 먼저 삭데죄는 후입 선출(LIFO)방식으로 리스트의 한쪽 끝으로만 자료의 삽입, 삭제 작업이 이루어지는 자료 구조
## 키워드
- LIFO, Top, Bottom, 삽입(Push), 제거(Pop)

## 개념도
![[Pasted image 20260323232856.png|500]]

| **구분**     | **설명**                                                     |
| ---------- | ---------------------------------------------------------- |
| **TOP**    | - 스택에서 삽입, 삭제가 일어나는 리스트의 끝<br>- **스택 포인터(stack pointer)**  |
| **Bottom** | - TOP의 반대쪽 리스트의 끝<br>- Bottom에선 삽입, 삭제가 일어나지 않음            |
| **PUSH**   | - 스택에서 값을 삽입(입력) 하는 것<br>- *Overflow : 스택 포인터 > 스택 크기      |
| **POP**    | - 스택에서 값을 삭제(출력) 하는 것<br>- *Underflow : Top pointer 주소 = 0 |
## 연산
![[Pasted image 20260323232913.png|500]]

| **구분**    | **항목**         | **설명**                                                                                                          |
| --------- | -------------- | --------------------------------------------------------------------------------------------------------------- |
| **연산**    | **push(item)** | - item 하나를 스택의 가장 윗 부분에 추가                                                                                      |
|           | **pop()**      | - 스택에서 가장 위에 있는 항목을 제거하고 Return                                                                                 |
|           | **init()**     | - 스택 초기화, 스택 포인터를 0으로 설정                                                                                        |
|           | **isEmpty()**  | - 스택이 비어 있을 때 true를 반환                                                                                          |
| **발생 예외** | **Overflow**   | - Stack Pointer의 값이 스택에서 할당 받은 메모리 부분의 마지막 주소보다 커져 스택의 모든 기억장소가 꽉 채워져 있는 상태<br>- 더 이상 자료를 삽입할 수 없어 Overflow를 발생 |
|           | **Underflow**  | - Stack Pointer의 주소 0을 가지고 있다면 스택에는 삭제할 자료가 없으므로 Underflow를 발생                                                  |
